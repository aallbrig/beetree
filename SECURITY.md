# Security policy

## Supported versions

Only the latest release receives security fixes. See the
[releases page](https://github.com/aallbrig/beetreecraft/releases) for the current version;
the live site at beetreecraft.com always runs the latest one.

## Reporting a vulnerability privately

Use GitHub private vulnerability reporting:
<https://github.com/aallbrig/beetreecraft/security/advisories/new>

Do not post vulnerability reports in public issues, pull requests, comments or the forum.
Anything posted publicly is visible to everyone and permanent in history.

## What to include

- What is affected (page, API route, CLI command, MCP tool) and the release version.
- Steps to reproduce, or a minimal proof of concept.
- The impact you expect: what an attacker could read, change or exhaust.
- Never include real credentials, other people's data, or data you were not authorised to access.

## What to expect

- Acknowledgement within 7 days.
- A fix or a status update within 30 days for confirmed issues.
- Credit in the release notes if you want it, after the fix is deployed.

Please test only against your own account and data, and avoid actions that degrade the
service for others, such as denial-of-service or automated scanning at volume.
